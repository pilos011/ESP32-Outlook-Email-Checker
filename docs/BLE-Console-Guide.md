# BLE 설정 콘솔 사용 가이드

**OutlookLED** 장치는 **BLE NUS (Nordic UART Service)** 를 내장하고 있어,  
스마트폰 앱(nRF Connect)으로 WiFi 비밀번호·근무시간·VIP·예약알림 등  
모든 설정을 **재빌드 없이** 무선으로 변경하고 NVS에 영구 저장할 수 있습니다.

## 1. 준비물

| 항목 | 내용 |
|------|------|
| 앱 | **nRF Connect for Mobile** (iOS / Android, 무료) |
| 장치명 | `OutlookLED` |
| BLE 서비스 | Nordic UART Service (NUS) |
| 보안 | 앱수준 PIN 인증 (암호화 없음, 사무실 내부 전용) |

---

## 2. nRF Connect 연결 방법

### 2-1. 스캔 및 연결

1. nRF Connect 실행 → **Scanner** 탭
2. `SCAN` 버튼 → 목록에서 **OutlookLED** 찾기
3. **CONNECT** 버튼 탭

### 2-2. TX 알림 구독 (응답 수신용)

> 이 단계를 건너뛰면 장치의 응답을 받을 수 없습니다.

1. 연결 후 **Client** 탭 → **Nordic UART Service** 펼치기
2. **TX Characteristic** (UUID `6E400003`) 찾기
3. TX 옆 ▼(다운로드) 아이콘 탭 → **Subscribe** 선택
4. TX 줄에 `Notifications enabled` 표시 확인

### 2-3. 명령 전송

1. **RX Characteristic** (UUID `6E400002`) 찾기  
   *(Properties: WRITE, WRITE NO RESPONSE)*
2. RX 옆 ↑(업로드) 아이콘 탭
3. 팝업 상단 → **TEXT** 선택 (기본값 HEX에서 변경)
4. Advanced 섹션 → **Write type: Command (No response)** 선택  
   *(또는 Request 중 하나, 둘 다 동작함)*
5. 입력창에 명령어 입력 → **SEND**

## 3. 인증 (AUTH)

BLE 연결 직후 **모든 명령보다 먼저** 인증이 필요합니다.

```
AUTH:PIN번호
```

예시:
```
AUTH:0197
```

**응답:**
- `OK 인증됨` — 이후 모든 명령 사용 가능
- `ERR: 잘못된 PIN` — PIN 불일치, 재시도 가능

**보안 정책:**
- 연결이 끊기면 인증 상태 자동 초기화 → 재연결 시 재인증 필요
- PIN은 `config.ini` `[ble]` → `pin` 항목으로 설정 후 재빌드

## 4. 명령어 전체 목록

> **형식 규칙**
> - 대·소문자 무시 (`status` = `STATUS`)
> - 콜론(`:`)으로 명령과 인수 구분
> - 모든 변경은 **NVS에 자동 저장** → 재부팅 후에도 유지

---

### STATUS — 현재 설정 조회

```
STATUS
```

**응답 예시:**
```
=== 현재 설정 ===
WiFi: MyOffice_2.4G
밝기:5 점멸:500ms 폴링:10s
근무:07:30~17:00
VIP(2):
 [0] boss@example.com
 [1] manager@example.com
예약(3):
 [0] 08:20 월
 [1] 11:30 평일
 [2] 12:30 평일
=================
```

---

### AUTH — 인증

| 형식 | `AUTH:PIN번호` |
|------|----------------|
| 예시 | `AUTH:0197` |
| 응답 | `OK 인증됨` / `ERR: 잘못된 PIN` |

---

### WIFI:ssid:pass — WiFi 변경

| 형식 | `WIFI:SSID이름:비밀번호` |
|------|--------------------------|
| 예시 | `WIFI:MyOffice_2.4G:password123` |
| 응답 | `OK 연결됨: 192.168.1.100` / `ERR: WiFi 연결 실패` |

> 즉시 재연결을 시도합니다. 연결 실패 시 이전 SSID는 이미 덮어써진 상태이므로  
> WIFI 명령으로 올바른 SSID를 다시 입력하거나 `RESET` 후 재부팅하세요.

---

### BRIGHT:n — LED 밝기

| 형식 | `BRIGHT:밝기값` |
|------|-----------------|
| 범위 | `0` (소등) ~ `255` (최대), 실사용 권장 `5~30` |
| 예시 | `BRIGHT:10` |
| 응답 | `OK brightness=10` |

---

### BLINK:ms — LED 점멸 주기

| 형식 | `BLINK:밀리초` |
|------|----------------|
| 범위 | `100` ~ `5000` (ms) |
| 예시 | `BLINK:300` (빠름) / `BLINK:1000` (느림) |
| 응답 | `OK blink=300ms` |

> 빨강·파랑 점멸 LED에만 적용됩니다. 초록(GREEN_SOLID)은 영향 없음.

---

### POLL:sec — 폴링 주기

| 형식 | `POLL:초` |
|------|-----------|
| 범위 | `5` ~ `3600` (초) |
| 예시 | `POLL:10` (10초마다 메일 확인) |
| 응답 | `OK poll=10s` |

---

### WORK:HHMM:HHMM — 근무시간

| 형식 | `WORK:시작시각:종료시각` (HHMM 4자리) |
|------|----------------------------------------|
| 예시 | `WORK:0800:1700` (08:00 ~ 17:00) |
| 응답 | `OK 근무:08:00~17:00` |

> 근무시간 외에는 LED 소등 + 폴링 중단됩니다.  
> `config.ini` → `work_hours_only = false` 설정 시 24시간 항상 동작 (이 명령 무효).

---

### VIP:list / add / del — VIP 발신인

VIP 발신인에서 메일이 오면 **빨간 LED 점멸 + 비프음**이 울립니다.

| 하위 명령 | 형식 | 예시 |
|-----------|------|------|
| 목록 조회 | `VIP:list` | `VIP:list` |
| 추가 | `VIP:add:이메일` | `VIP:add:boss@example.com` |
| 삭제 | `VIP:del:이메일` | `VIP:del:boss@example.com` |

**응답 예시:**
```
[0] boss@example.com
[1] manager@example.com
```
```
OK VIP추가: boss@example.com
```

> - 이메일은 소문자로 자동 변환됩니다.
> - 최대 **8개**까지 등록 가능합니다.

---

### SCHED:list / add / del / clear — 예약 알림

지정 시각에 **부저 2회 비프**가 울립니다. 최대 **8개** 등록 가능.

#### 목록 조회

```
SCHED:list
```

**응답 예시:**
```
[0] 08:20 월
[1] 11:30 평일
[2] 12:30 평일
[3] 17:00 평일
```

#### 예약 추가

```
SCHED:add:HHMM:요일코드
```

**요일 코드:**

| 코드 | 의미 |
|------|------|
| `0` | 일요일 |
| `1` | 월요일 |
| `2` | 화요일 |
| `3` | 수요일 |
| `4` | 목요일 |
| `5` | 금요일 |
| `6` | 토요일 |
| `7` | 평일 (월~금, 가장 많이 사용) |

**예시:**

| 입력 | 의미 |
|------|------|
| `SCHED:add:0820:1` | 매주 **월**요일 08:20 |
| `SCHED:add:1130:7` | 매주 **평일** 11:30 |
| `SCHED:add:1230:7` | 매주 **평일** 12:30 |
| `SCHED:add:1700:5` | 매주 **금**요일 17:00 |

**응답:** `OK 추가:11:30 평일`

#### 예약 삭제

```
SCHED:del:인덱스번호
```

예시: `SCHED:del:2` → `[2]` 번 예약 삭제

> 삭제 후 인덱스가 자동으로 앞당겨집니다. 삭제 전에 `SCHED:list`로 번호 확인 권장.

#### 전체 삭제

```
SCHED:clear
```

응답: `OK 예약 전체 삭제`

---

### RESET — NVS 초기화

```
RESET
```

NVS에 저장된 **모든 설정을 삭제**하고 즉시 재부팅합니다.  
재부팅 후에는 `config.ini`에 컴파일된 기본값으로 동작합니다.

> ⚠️ WiFi 비밀번호·VIP·예약 등 모든 BLE 설정이 초기화됩니다.

---

### REBOOT — 재부팅

```
REBOOT
```

설정 변경 없이 즉시 재부팅합니다. NVS 내용은 유지됩니다.

## 5. 설정 저장 방식

```
┌──────────────┐   빌드 시 적용   ┌─────────────────────┐
│  config.ini  │ ─────────────→  │ config_generated.h  │ (펌웨어에 내장)
└──────────────┘                 └─────────────────────┘
                                           │ 기본값
                                           ↓
                                 ┌─────────────────────┐
                                 │   NVS (Flash)        │ ← BLE 명령으로 덮어씀
                                 └─────────────────────┘
                                           │ 부팅 시 로드
                                           ↓
                                 ┌─────────────────────┐
                                 │  런타임 동작         │
                                 └─────────────────────┘
```

- BLE로 변경한 값은 **즉시 적용 + NVS 저장** → 재부팅 후에도 유지
- `RESET` 명령 또는 NVS 파티션 삭제 시 `config.ini` 기본값으로 복귀
- `config.ini` 변경 후 재빌드·업로드하면 **NVS 값이 우선** (기본값 교체 안 됨)  
  → NVS 값을 초기화하려면 먼저 `RESET` 명령 실행

## 6. 자주 묻는 질문

**Q. 명령을 보냈는데 TX에 아무 반응이 없어요.**  
→ TX Characteristic을 **Subscribe** 했는지 확인하세요 (2-2 단계).  
→ RX 전송 시 **TEXT 모드**로 입력했는지 확인하세요.

**Q. `ERR: 인증 필요` 가 계속 나와요.**  
→ 연결 후 가장 먼저 `AUTH:PIN번호`를 전송해야 합니다.

**Q. WiFi를 잘못 입력해서 연결이 안 돼요.**  
→ BLE는 WiFi와 무관하게 항상 동작합니다. `WIFI:올바른SSID:비밀번호` 재입력 또는 `RESET` 후 재부팅.

**Q. 예약을 추가했는데 알림이 안 울려요.**  
→ 현재 근무시간 내인지 확인 (`STATUS`로 근무시간 확인).  
→ `SCHED:list`로 등록된 시각과 요일 코드 확인.  
→ 분 단위까지 정확히 맞아야 울립니다 (±30초 오차 허용).

**Q. PIN을 바꾸고 싶어요.**  
→ `config.ini` → `[ble]` → `pin = 새PIN` 수정 후 재빌드·업로드.  
→ BLE를 통한 런타임 PIN 변경은 지원하지 않습니다.

**Q. 장치가 BLE 목록에 안 보여요.**  
→ 이미 다른 기기가 연결 중이면 광고가 중단됩니다. 먼저 연결된 기기를 끊으세요.  
→ 장치를 재부팅하면 광고가 재시작됩니다.
